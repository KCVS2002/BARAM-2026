# BARAM 2026 방법론 탐색

작성일: 2026-07-11 · 상태: 초안 (사용자 검토 전)

## 1. 문제의 재정의

- **본질**: 하루 전(D-1 13:00 기준) 발표된 기상예보만으로 D일 24시간의 풍력발전량을 맞추는
  **day-ahead 예측** 문제. 예보-발전량 매핑이 핵심이고, 실측 lag 피처는 테스트에서 사용 불가.
- **단지 특성**: 태백 가덕산 풍력 (강원도 산악 복잡지형, 해발 ~1,000m 능선).
  - group_1: VESTAS V126 3.6MW × 6기 (1~6호기), 허브 117m
  - group_2: VESTAS V126 3.6MW × 6기 (7~12호기), 허브 117m
  - group_3: UNISON U136 4.2MW × 5기, 허브 117m
  - 세 그룹이 같은 능선에 있어 상관이 매우 높을 것 → 그룹 간 정보 공유(멀티태스크) 여지.
- **평가의 특수성** (이 대회의 진짜 게임):
  1. `Score = 0.5×(1-NMAE) + 0.5×FICR`, **실제발전량 ≥ 설비용량 10%인 시간만 평가**.
  2. FICR: 오차율 ≤6% → 4원, ≤8% → 3원, >8% → 0원 (실제발전량 가중).
  3. 즉 점수의 절반은 "평균 오차"가 아니라 **±6%/8% 밴드 적중률**. MAE 최적해(중앙값 예측)와
     FICR 최적해(분포의 최빈 구간 적중)는 다르다 → **확률예측 + 의사결정 최적화**가 필요.

### Baseline의 약점 (개선 기회)

- 16개 LDAPS / 9개 GFS 격자를 단순 평균 → 공간 정보 소실. u, v를 각각 평균 → 풍속 크기 왜곡
  (벡터 평균 ≠ 스칼라 풍속 평균).
- **풍속·풍향 자체를 피처로 만들지 않음** (u,v 원값만 사용). 풍력의 물리(P ∝ ρv³)를 전혀 반영 안 함.
- 요일/주말 피처는 풍력과 무관한 노이즈.
- SCADA 데이터 미사용, 검증 절차 없음, RF는 이 문제에서 GBM 대비 열세.

## 2. 선행연구 / 유사 대회 조사

### 2.1 예보 기반 풍력 예측 대회의 정석 (일관된 결론)

| 대회 | 우승권 접근법 |
|---|---|
| **GEFCom2014 Wind** | 격자 NWP 피처 + gradient boosting(GAM-tree 앙상블), 확률예측(퀀타일) |
| **EEM20 Wind** | 퀀타일 조합(quantile combination) 앙상블 |
| **HEFTCom2024** (IEEE, 2024) | **다중 NWP 소스별 sister model → 스태킹**, LightGBM 퀀타일 회귀 대량(808개) 학습, 퀀타일 병합. GBT가 여전히 최강임을 재확인 |
| **WindAI Challenge** (노르웨이) | Histogram GB + 퀀타일 회귀, 풍력단지별 공간 피처, ±6h 풍속 이동평균, 용량계수 정규화 |
| **KDD Cup 2022** (Baidu) | GBDT + RNN 앙상블 — 단 이 대회는 SCADA 기반 초단기 예측이라 우리와 세팅이 다름 (참고만) |

**요약**: NWP 기반 day-ahead 풍력 예측에서는 (1) **LightGBM류 GBT + 퀀타일 회귀**가 검증된 최강 베이스,
(2) **다중 NWP 소스 각각 모델 학습 후 앙상블/스태킹**이 반복 검증된 승리 공식,
(3) 딥러닝(Transformer 등)은 SCADA 초단기에서는 유효하나 NWP day-ahead 세팅에선 GBT를 잘 못 이김.

### 2.2 복잡지형 풍속 보정 연구

- NWP의 지상풍(10m)은 산악 지형에서 허브고도(117m) 풍속과 괴리가 큼. Power law/로그 프로파일로
  물리적 외삽 후 **ML이 잔차(비정상 대기안정도 효과)를 보정**하는 하이브리드가 효과적.
- 다행히 GFS에는 80m/100m 바람, LDAPS에는 50m 바람과 경계층 높이(blh)가 있어 연직 시어(shear)를
  직접 피처화 가능.
- 공기밀도 보정: ρ = p/(R·T) → 밀도보정 풍력밀도 `ρ·v³`이 표준 피처.

### 2.3 국내 예측제도(정산금) 관련

- FICR 산식은 실제 KPX 재생에너지 발전량 예측제도(오차 6%/8% 기준 4원/3원)를 그대로 반영한 것.
- 업계(해줌 등)에서도 "오차율 밴드 적중"이 수익의 핵심 — 우리 대회에서 이걸 **명시적 의사결정
  문제로 푸는 팀은 드물 것** → 주요 차별화 포인트.

## 3. 제안 파이프라인

```
[1] 데이터 정합/EDA
    LDAPS·GFS 격자별 정리, SCADA-라벨 정합성 확인, 결측/이상치(curtailment·정지) 파악

[2] 피처 엔지니어링 (물리 기반)
    - 격자별 풍속·풍향 (u,v → speed, sin/cos dir), 벡터→스칼라 순서 주의
    - 다중 고도 풍속 + 연직 시어/베그 지수, 허브고도(117m) 외삽 풍속
    - 공기밀도(온도·기압) 및 ρv³, 돌풍(gust), 경계층높이, 대기안정도 프록시
    - 격자 평균 대신: 터빈 최근접 격자 + 격자별 개별 피처 + 격자간 분산(예보 불확실성 프록시)
    - 시간축 문맥: 같은 예보 사이클 내 t±1~3h 풍속 (이동평균/차분) — 리드타임 내라 누수 아님
    - 예보 리드타임(13~36h) 피처: 리드타임이 길수록 오차 큼
    - 캘린더: 시각·월 sin/cos만 (요일·주말 제거)

[3] 모델 (그룹별 × 소스별 sister models)
    - LightGBM 퀀타일 회귀 (q=0.05~0.95 촘촘히) — 메인
    - LDAPS-only / GFS-only / 결합 모델 → 스태킹 or 가중 병합 (HEFTCom 방식)
    - 보조: CatBoost/XGBoost, 간단한 MLP — 앙상블 다양성용
    - 타깃: 발전량/설비용량 (capacity factor) 정규화 학습 → 그룹 간 데이터 공유 가능

[4] FICR 의사결정 최적화 ★ 핵심 차별화
    - 퀀타일 예측 → 시간별 예측분포 구성
    - 제출값 g를 분포 위에서 수치 최적화:
      argmax_g  E[ 0.5·(-|g-A|/C) + 0.5·A·price(|g-A|/C) | A ≥ 0.1C 조건 반영 ]
    - MAE만 보면 중앙값이 최적이지만 FICR 항이 분포가 좁은 시간대엔 밴드 중심으로,
      분포가 넓은 시간대엔 기대손실 최소점으로 제출값을 이동시킴
    - 평가 필터(A ≥ 0.1C)도 기대값 계산에 반영 (저풍속 시간대는 점수 기여 확률 자체가 낮음)

[5] 검증
    - Rolling-origin 시계열 CV (예: 2022-23 학습 → 2024 검증을 월 단위로 확장)
    - 항상 대회 metric() 그대로 측정 + NMAE/FICR 분해 리포트
    - 실험 로그 관리, 리더보드 제출은 CV 개선 확인 시에만 (일 5회 제한)
```

### SCADA 활용 방안 (train 전용 데이터를 우회 활용)

SCADA는 테스트 기간에 없으므로 직접 피처로는 못 쓰지만:

1. **실측 파워커브 구축**: 터빈별 풍속→출력 곡선을 SCADA로 적합 → NWP 예보풍속을 넣어
   "물리 기반 예측 발전량" 피처 생성 (test에서도 계산 가능).
2. **2단계 모델**: (a) NWP → 단지 실측 풍속(SCADA ws) 예측 모델 학습 → test에 적용해
   "보정된 단지 풍속" 피처 생성 → (b) 보정 풍속 → 발전량. NWP 편향을 명시적으로 제거.
3. **가용성/이상 데이터 정제**: SCADA로 정지·출력제한(curtailment) 시간대 탐지 →
   해당 라벨을 학습에서 제외하거나 다운웨이트 (라벨 노이즈 제거).
4. **그룹 내 터빈 합 vs 라벨 검증**: 라벨의 집계 방식·손실률 파악.

## 5. 차별화 포인트 정리 (우선순위)

1. **FICR 의사결정 최적화** — 퀀타일 분포에서 기대점수 최대화 제출값 산출.
   대부분 팀이 MAE 최소화(점 예측)에 머물 가능성 높음. 이론상 FICR 절반 배점에서 확실한 우위.
2. **다중 NWP 앙상블** — 제공 LDAPS+GFS에 ECMWF/ICON(Open-Meteo) 추가 시 sister-model 스태킹.
   HEFTCom2024에서 검증된 승리 공식.
3. **물리 기반 피처 + SCADA 파워커브 2단계 모델** — 복잡지형 NWP 풍속 편향을 SCADA로 명시 보정.
4. **라벨 정제** — SCADA로 curtailment/정지 시간 탐지해 학습 라벨 노이즈 제거.
5. **격자 공간 정보 보존** — 평균 대신 터빈-격자 매칭, 격자간 분산(예보 불확실성) 피처.

## 6. 리스크 / 확인 필요 사항 (상세)

각 항목: **무엇이 문제인가 → 어떻게 드러나는가 → 어떻게 대응하는가**.

### R1. 평가 필터(A ≥ 설비용량 10%)는 추론 시점에 적용 불가 — "예측은 전 구간, 평가는 일부"

- **문제**: `metric()`의 필터는 **실제 발전량** A 기준이다. 우리는 A를 모르니 test에서 어떤 시간대가
  평가 대상인지 알 수 없다 → 8,760시간 전부 예측해야 한다.
- **드러남**: 저풍속 시간대(발전량 낮음)를 아무리 잘 맞춰도 평가에서 빠질 확률이 높다.
  반대로 발전량이 큰 시간대의 오차가 점수를 지배한다(FICR은 A 가중이라 더 심함).
- **대응**: (1) 손실함수·CV를 **발전량 큰 구간에 가중**하거나, 최소한 리포트를 A≥0.1C 구간으로 필터해
  실제 대회 점수와 정렬시킨다. (2) FICR 최적화(3.[4])에서 "이 시간대가 평가에 포함될 확률
  P(A≥0.1C)"을 예측분포로 추정해 기대점수에 반영한다. (3) 저발전 구간 과최적화에 자원 낭비 금지.

### R2. u·v 벡터 평균 → 풍속 과소추정 (baseline이 실제로 범한 오류)

- **문제**: 격자별 (u,v)를 평균한 뒤 풍속을 계산하면, 풍향이 조금만 달라도 벡터합이 상쇄돼
  실제 풍속보다 작아진다. 풍력은 `P ∝ v³`이라 이 편향이 3제곱으로 증폭된다.
- **대응**: **격자마다 먼저 스칼라 풍속 `√(u²+v²)` 계산 → 그 다음 격자 평균**. 벡터 평균이 필요하면
  풍향 분산·발산 지표로 따로 만든다. 고도별(10/50/80/100m)로 각각 스칼라화.

### R3. 라벨 노이즈: 출력제한(curtailment)·정지·정비

- **문제**: 실제 발전량은 바람이 좋아도 계통 제약·정비·고장으로 0이나 저출력이 될 수 있다.
  NWP는 "바람 강함"인데 라벨은 0 → 모델이 이 관계를 학습하면 정상 시간대 예측이 망가진다.
- **드러남**: 파워커브 산점도에서 정격풍속인데 출력 0인 점들, 계단형 상한(제한값)으로 나타남.
- **대응**: SCADA(풍속 vs power)로 curtailment/정지 구간 탐지 → 학습에서 **제외 또는 다운웨이트**.
  단, test에는 이 정제를 적용할 수 없으므로(우리가 미래 제한을 모름) 학습 라벨 정제 목적만.
  이 불확실성 자체를 퀀타일 예측의 하한 넓힘으로 흡수.

### R3b. 그룹 라벨의 집계·손실 관계 미확인

- **문제**: `train_labels`의 그룹 발전량이 SCADA 터빈 출력의 단순 합인지, 손실률·정산 기준이
  반영된 값인지 불명. SCADA는 kW10m(10분), 라벨은 시간 kWh → 집계 규칙 검증 필요.
- **대응**: EDA에서 그룹별 (SCADA 터빈 합 ↔ 라벨) 상관·스케일을 맞춰보고 SCADA 활용 방식을 확정.

### R4. 외부 NWP의 누수-안전 사이클 정합 (가장 조심할 부분)

- **확정 사실**: 제공 데이터 = **D-1 09 KST(00 UTC) 초기화, D-1 13 KST(04 UTC) 사용가능**,
  대상 D일 01시~D+1일 00시 = **GFS 00Z run의 예보시간 f016~f039**.
- **문제**: 외부 NWP를 붙일 때 이보다 **늦게 발표된 사이클을 쓰면 즉시 누수·실격**.
  예: D일 00 UTC(=09 KST) run은 D일 오전 대상엔 미래 정보 → 사용 불가.
- **대응**: 외부 GFS/IFS는 **반드시 D-1 00 UTC 사이클, f016~f039만** 추출해 제공 데이터와 동일 기준
  유지. Open-Meteo Previous Runs는 리드타임 라벨(day1/day2)이 이 기준 이전인지 사이클 타이밍을
  개별 검증(안 되면 day2 사용, 정확도↓ 감수). 수집 근거를 `external_data/README.md`에 기록.

### R5. 외부 아카이브의 기간 커버리지 부족

- **문제**: Open-Meteo Previous Runs는 대부분 모델이 **2024-01부터** 아카이브 → 학습기간(2022~2024)
  중 2024만 커버. NOAA GFS S3는 2021경부터라 전 기간 가능하나 용량이 큼.
- **드러남**: 외부 피처가 특정 연도에만 존재 → train 내 결측 불균형, CV 왜곡.
- **대응**: 외부 피처는 "있으면 쓰고 없으면 결측" 처리하되, **결측 여부 자체를 연도 교란요인**으로
  보고 시계열 CV로 이득을 검증. 커버리지가 전 기간인 NOAA GFS를 우선.

### R6. group_3 라벨 2023년부터 (학습량 부족)

- **문제**: group_3(UNISON)은 2022년 라벨이 빈칸 → 다른 그룹의 2/3 학습량.
- **대응**: **capacity-factor(발전량/설비용량)로 정규화**해 3그룹을 한 모델로 공유 학습(그룹 원-핫/
  임베딩 추가) → group_3이 group_1·2의 패턴을 차용. 그룹별 개별 모델과 앙상블.

### R7. 분포 이동 (2025 test ≠ 2022–24 train)

- **문제**: 연도별 기후 변동(엘니뇨 등), 터빈 가용성 변화, NWP 모델 업그레이드로 test 분포가 다를 수 있음.
- **대응**: 시계열 CV의 최종 fold를 test 직전(2024 후반)으로 두고 일반화 확인. 계절·월별 오차 분해.
  예보-발전량의 물리적 관계(파워커브)는 상대적으로 안정적이므로 물리 피처 위주가 이동에 강함.

### R8. FICR 최적화의 과최적화 위험

- **문제**: 퀀타일 분포가 잘못 캘리브레이션되면 기대점수 최적화가 오히려 리더보드를 떨어뜨림.
- **대응**: 퀀타일 캘리브레이션(신뢰구간 커버리지) 먼저 점검. 최적화는 CV에서 점 예측 대비
  **실제 대회 metric 개선**이 확인될 때만 채택. Public 40%/Private 60% 분할이라 과적합 시 역전 주의.

### R9. CV 분산 (평가 유효 시간대의 계절 편중)

- **문제**: A≥0.1C 시간대가 겨울(강풍)에 몰림 → fold별 유효표본 수·점수가 크게 출렁.
- **대응**: 월 단위 rolling-origin으로 계절을 고르게 덮고, fold별 점수 분산까지 리포트. 단일 fold 신뢰 금지.

### R10. 정산기준 개정 무시

- 2025-06 예측제도 개정과 무관하게 **대회 산식(6%/8%, 4원/3원)만** 사용. `metric()`이 유일 기준.

## 7. 제안 진행 순서

1. EDA + 데이터 정합성/SCADA-라벨 관계 파악, 시계열 CV 프레임 + metric 리포트 구축
2. 물리 피처 + LightGBM 퀀타일 베이스라인 (제공 데이터만) → 첫 제출로 리더보드 캘리브레이션
3. FICR 최적화 레이어 추가 → 점수 개선폭 측정
4. SCADA 파워커브/2단계 보정 + 라벨 정제
5. 외부 NWP(기상청 API허브, NOAA GFS, Open-Meteo) 수집·검증 → sister model 앙상블
6. 스태킹/후처리 튜닝, 제출 전략 정리
